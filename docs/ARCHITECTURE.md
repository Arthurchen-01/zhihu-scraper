# 目标架构

> 状态：重建中的目标架构。本文描述模块职责和稳定 seam，不代表所有能力已经完成。

## 1. 外部 interface

对 CLI、Agent 或未来其他调用者，只暴露一个归档行为：

```text
archive(URL, settings) → ArchiveReport
```

调用者只需要提供知乎 URL 和少量用户设置。URL 类型识别、登录态、浏览器回退、媒体下载、目录创建和保存顺序都隐藏在归档模块内部。

## 2. 主流程

```text
知乎 URL
  → URL 路由
  → HTTP 抓取 / 浏览器回退
  → 归一化内容模型
  ├→ 媒体下载
  ├→ Markdown 渲染
  ├→ HTML 渲染
  └→ SQLite 保存
```

模块 seam：

- URL 路由：把输入识别为文章、回答、问题、专栏或独立视频目标。
- 知乎来源 Adapter：获取原始数据，不负责输出格式。
- 归一化模块：把不同知乎载荷转换为同一种内容模型。
- 媒体模块：解析、下载、续传和校验图片、动图与独立视频。
- Markdown 渲染器：只根据内容模型生成 Markdown。
- HTML 渲染器：只根据内容模型生成静态 HTML 和本地资源引用。
- SQLite 保存器：保存结构化内容、评论、媒体、来源和确定性关系。
- 运行平台 Adapter：封装 Windows、macOS、Linux 的真实差异。

CLI 只编排归档行为，不包含抓取、转换或文件命名规则。

## 3. 归一化内容模型

内容模型表达知乎内容的含义，而不是某个接口的 JSON 形状。第一阶段至少覆盖：

- 稳定知乎标识与原始 URL
- 内容类型与标题
- 作者和发布时间
- 正文块：段落、标题、列表、引用、表格、代码和数学公式
- 图片、动图和独立视频
- 问题与回答关系
- 文章与多个收录专栏的关系
- 一级评论与二级回复

渲染器和保存器只能依赖内容模型，不能读取 HTTP 响应、Cookie 或浏览器对象。

## 4. 归档目录

整个归档库共用一个 SQLite 文件：

```text
知乎归档/
├── zhihu.db
└── ...
```

只有整个专栏使用 `内容/`：

```text
知乎归档/
├── zhihu.db
└── 机器学习/
    ├── 机器学习.md
    ├── 机器学习.html
    ├── 内容/
    │   ├── 一文归纳AI数据增强之法.md
    │   ├── 一文归纳AI数据增强之法.html
    │   └── ...
    ├── media/
    └── assets/
```

专栏文章顶部使用紧凑元信息：

```text
收录专栏：专栏 A、专栏 B
本次归档自：机器学习 · 本栏目共 81 篇 · 查看完整目录
```

单篇文章、单个回答、问题下多个回答和单个视频使用精简结构：

```text
标题/
├── 标题.md
├── 标题.html
├── media/
└── assets/
```

问题下多个回答合并为同一个问题 Markdown/HTML，不创建 `内容/`。`media/` 和 `assets/` 只在有对应产物时创建。

文件名优先使用可读标题。统一文件名策略采用三个系统都安全的规则；只有发生同名、系统保留名称或长度超限时，才追加知乎 ID 或安全截断。

## 5. 三平台 Adapter

程序启动时检测一次运行平台：

```text
RuntimePlatform.detect()
  ├→ Windows Adapter
  ├→ macOS Adapter
  └→ Linux Adapter
```

平台 Adapter 只负责真正变化的行为：

- 浏览器发现、安装和进程管理
- 用户数据与缓存目录
- 凭证安全存储能力
- 平台特有的文件占用与路径行为

URL、内容模型、渲染、SQLite 和知乎字段解析保持共用。业务模块中不得散落操作系统判断。

## 6. 设置原则

普通用户可见设置保持少而稳定：

- 保存目录
- Markdown、HTML、SQLite、PDF 输出开关
- 评论开关及 10/10 数量
- 浏览器登录方式
- 代理开关

默认生成 Markdown、HTML 和 SQLite；PDF、评论、代理默认关闭。图片、动图、公式、最高可用视频清晰度、断点续传、原链接和日志脱敏属于固定可靠行为，不制造多余开关。

请求并发、重试、超时、CDP 和浏览器目录属于高级设置。分块大小、数据库结构和平台类型属于内部策略。

## 7. 迁移与验证

每项能力按照一个纵向闭环迁移：

1. 用公共 interface 写一个行为测试。
2. 实现通过该测试的最小新路径。
3. 加入一个真实但可控的集成样例。
4. 删除已经被替代的旧实现。
5. 提交并推送。

第一阶段不实现关键词搜索、语义搜索或知识图谱。后续范围统一记录在 `docs/FEATURE_TODO.md`。
