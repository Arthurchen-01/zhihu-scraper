# AGENTS.md — 给用户的 AI Agent 看

你正在帮一位用户（清一新教育 · 冠军班）部署一个**已经写好的**浏览器扩展。
**你不需要写任何代码**，只需要把这个文件夹装进他的浏览器。

装完之后，用户双击桌面上的「清一新教育」一键程序时，
就**再也不需要关闭浏览器**了。

---

## 0. 这个扩展做什么（30 秒理解）

浏览器会**独占锁定**自己的 Cookie 数据库，任何外部程序都读不到里面的知乎登录态
（这是操作系统层面的锁，Python 直读 / 复制文件 / CreateFileW / sqlite immutable
四种方式我们都实测过，全部失败）。

而这个扩展跑在浏览器内部，读自己的 Cookie 是分内之事。于是：

```
扩展读到知乎登录 → POST 到控制台凭证柜 → 一键程序从云端取用
```

一键程序从此不碰浏览器，浏览器就不用关了。

> ⚠️ 扩展**不会**把密码交出去，只上传知乎发给本机的登录凭据（Cookie），
> 云端 6 小时后自动丢弃。

## 1. 前置检查（先做，避免白干）

1. 确认扩展文件夹完整，应包含：
   `manifest.json`、`config.js`、`background.js`、`popup.html`、`popup.js`、
   `options.html`、`options.js`、`help.html`、`icons/`（4 个 png）
2. 确认用户平时用的是 **Edge 还是 Chrome**，以及**知乎在哪个浏览器里登录**。
   扩展必须装进「已经登录知乎的那个浏览器」。
3. **强烈建议**：先把本文件夹从压缩包里解出来，放到一个**不会被删掉的固定位置**：

   ```
   %LOCALAPPDATA%\QingyiEdu\extension
   ```

   一键程序的工作目录也是 `%LOCALAPPDATA%\QingyiEdu`，放一起最省心。
   （注意：Chrome/Edge 只记住"你当初选的那个文件夹"，如果把文件夹移走或删掉，
   扩展会失效。）

## 2. 安装（三种方式，按可行性排序）

### 方式 A：引导用户点 3 下（最稳，推荐）

```powershell
# 1) 复制到固定位置
$dst = "$env:LOCALAPPDATA\QingyiEdu\extension"
New-Item -ItemType Directory -Force -Path (Split-Path $dst) | Out-Null
Copy-Item -Recurse -Force "<扩展所在目录>\*" $dst

# 2) 把路径放进剪贴板，用户待会不用手输
Set-Clipboard -Value $dst

# 3) 打开扩展管理页
start msedge "edge://extensions"     # Chrome 用户改成: start chrome "chrome://extensions"
```

然后请用户（或用你的鼠标控制能力）完成：

1. 打开右上角 **「开发人员模式 / Developer mode」** 开关；
2. 点 **「加载解压缩的扩展 / Load unpacked」**；
3. 在文件对话框地址栏 **Ctrl+V 粘贴**（已在剪贴板里），回车，选文件夹。

装好后工具栏应出现「清一新教育 · 修改助手」图标。

### 方式 B：用键盘自动化替你点（半自动，Windows）

如果你能执行 PowerShell + 有桌面交互权限，可用 `install-extension.ps1`
（同目录）帮你把文件夹放好、开页面、放剪贴板。
剩下那 3 下仍需人来点 —— **Chrome 禁止任何脚本注入 `chrome://` / `edge://` 页面，
所以文件选择框无法纯代码点掉**，这是浏览器故意设的防注入限制，不要浪费时间尝试。

### 方式 C：`--load-extension` 命令行（**通常不可用，先别试**）

`msedge --load-extension=<dir>` / `chrome --load-extension=<dir>` 看起来很美，
但有两个坑：

- 它必须搭配一个**独立的 `--user-data-dir`**，那个新配置里**没有知乎登录**，
  扩展装了也同步不出东西；
- 而配合用户**已有**的配置文件时，较新的 Chrome/Edge 出于安全已**禁用**该参数。

所以默认不要走这条路。只有在用户愿意在一个新配置里重新登录知乎时才可以考虑。

## 3. 装完必须验证（别跳）

1. 点工具栏上的扩展图标，弹窗里应看到：
   - **本浏览器知乎登录：已登录（N 条 Cookie）** ← 如果是「未登录」，
     说明装错浏览器了，或者用户没在这个浏览器登录知乎，回去处理；
   - **云端凭证柜：刚刚**
2. 若显示未同步：点「立即同步到云端」，应出现绿色提示
   `已同步成功（编号 xxxx…）`。
3. 命令行独立复核（可选，但推荐）：

   ```powershell
   curl.exe -s -H "X-API-Key: guanjun2026" `
     https://zh.samuraiguan.cloud/api/qy/credential-latest
   ```

   返回 `"ok":true` 且 `"note":"浏览器扩展"` 即为成功。
   （`age` 是距今秒数，`token` 是凭证编号。）

4. 最后告诉用户：**以后双击一键程序就行，不用关浏览器了。**

## 4. 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 弹窗显示「未登录」 | 装到了没登录知乎的浏览器；或该浏览器没登录 | 换到已登录知乎的浏览器重装，或先登录知乎 |
| 点同步报「连不上控制台」 | 网络 / 站点地址被改 | 设置页恢复默认地址 `https://zh.samuraiguan.cloud` |
| 报 403 | 站点密钥不对 | 设置页确认密钥为 `guanjun2026` |
| 云端一直是「未同步过」 | 扩展装了但未点同步；或定时同步被关 | 点「立即同步」；设置页把「自动同步」打开 |
| 图标不见了 | 扩展文件夹被移动/删除 | 重新加载已解压的扩展（文件夹放到固定位置） |
| 用户重新登录了知乎 | 旧凭证失效 | 扩展会自动重同步；也可手动点一次同步 |

## 5. 不要做的事

- ❌ 不要把扩展文件夹放在「下载」目录里就完事（清空下载会失效）。
- ❌ 不要试图用脚本注入 `chrome://extensions` —— 浏览器的安全策略禁止，必然失败。
- ❌ 不要改 `manifest.json` 里的 `host_permissions`，否则读不到知乎 Cookie。
- ❌ 不要把这个扩展提交到应用商店 —— 没必要，也过不了审（自用工具）。
